# 数据库架构

## 决策

服务端只支持 PostgreSQL。`DATABASE_URL` 必须使用 `postgres://` 或 `postgresql://`，其它 scheme 直接拒绝启动。数据库不迁移历史数据，也不在不同数据库之间搬数据；更换数据库意味着创建新的空库和新部署。

服务端采用 SeaORM 管理连接、实体映射和事务。SeaORM 是存储基础设施，不进入路由、协议桥接和领域模型。

## 适用边界

PostgreSQL 用于正式部署和本地开发；连接、备份、可用性和访问控制由部署环境负责。

身份隔离、供应商密钥加密、接入点模型解析、请求记录和统计口径不因部署环境改变。

## 分层

```text
路由、协议桥接、后台任务
        ↓
Storage 领域操作
        ↓
SeaORM 连接、实体与事务
        ↓
PostgreSQL
```

`Storage` 是服务端唯一的持久化入口。它以业务操作表达职责，例如注册身份、原子保存供应商及模型、保存接入点映射、解析候选供应商、写入会话和查询统计。

`AppState` 只持有 `Storage`，不暴露 `DatabaseConnection`、连接池或实体。路由、协议桥接和观测模块不得绕过 `Storage` 直接访问数据库。

不引入通用 `CrudRepository<T>`。Provider、接入点、身份和统计的约束不同，泛型 CRUD 会掩盖事务边界、身份范围和引用校验。SeaORM 实体只用于存储映射，不直接作为 API DTO 或领域对象返回。

## 数据模型

现有业务事实继续由以下资源表达：

- 身份及设备凭据摘要。
- 供应商、加密后的 API Key 与该供应商启用的模型清单（`models_json`）。
- 接入点、接入点模型映射与最近成功候选供应商。
- Responses 会话、请求记录和统计所需元数据。

资源 ID 继续使用 UUID 字符串，避免让自增主键语义进入 API。时间在领域层统一使用 UTC；DTO 按既有格式序列化。结构化元数据使用 JSON 值。密文、凭据哈希和令牌保持不透明字符串，不作为 ORM 关系或 JSON 字段处理。

实体关系、唯一约束、外键和索引由统一 schema 初始化模块定义。全新空库首次启动时创建完整当前 schema；已有完整 schema 在启动时执行幂等迁移（补齐缺失列、删除已废弃的遗留表、清理已退出链路的字段、按目录回填模型清单、按供应商清单对账接入点模型）；仅存在部分业务表时拒绝启动，要求创建新的部署。每一项跨资源写入仍须由单个事务完成；失败时不得留下部分供应商、空接入点或失配的模型映射。

## 连接与启动

`DATABASE_URL` 是唯一数据库选择来源：

```text
postgres://<user>:<password>@<host>:5432/<database>
```

缺失、未知 scheme、无法连接或数据库版本不满足要求时启动失败，不回退到其它数据库。

连接池容量由 `DATABASE_MAX_CONNECTIONS` 控制，按部署实例配置。主密钥、监听地址和上游策略保持现有独立配置，不从数据库配置推导。

## 初始化与发布

服务启动时为全新空库创建当前完整 schema，并在基础 schema 初始化后执行版本化的 `provider_catalog_v1` 数据迁移。迁移在单个事务中校验旧供应商类型和供应商引用，清理目录外模型及旧接入点别名后归一化供应商目录 ID 并记录版本。

迁移遇到未知供应商或无法定位供应商的数据时启动失败并回滚；供应商模型、接入点模型和模型别名中不在目录内的记录会在同一事务内删除，无法无损迁移的旧接入点别名也会删除。

基础 schema 不接受部分初始化数据库；schema 结构变化和超出 `provider_catalog_v1` 范围的升级需要另行设计。

## 查询规则

常规读取、写入、关联和事务优先使用 SeaORM 的查询构造器，SQL 保持 PostgreSQL 语义。需要方言表达式时（例如按北京时间分桶的统计聚合），表达式集中在存储层的对应模块中，不在路由或协议转换逻辑里拼接 SQL。

禁止在业务判断中使用 `information_schema`、`pg_*` 目录表或其它数据库元数据查询；它们只允许出现在 schema 初始化与校验代码中。

## 验证矩阵

至少覆盖以下事实：

- 全新数据库可以初始化完整 schema 并启动服务。
- 身份、供应商、接入点、模型映射、会话和请求记录具有相同的约束与可见范围。
- 供应商及模型、接入点及映射的完整保存保持事务原子性。
- 设备凭据轮换、接入点令牌认证、候选供应商解析和失活身份清理保持既有语义。
- 请求记录、时间范围和统计聚合返回一致结果。
- 重复资源、跨身份访问、无效引用和数据库约束失败均返回既有稳定错误码，且不泄露数据库细节。

测试必须连接专用 PostgreSQL 测试库（`TEST_POSTGRES_URL`）：每个用例创建并清理自己的 `prelay_test_*` schema，缺失该变量时测试直接失败。mock 测试不能证明 PostgreSQL 部署可用；发布前仍须在全新空 PostgreSQL 数据库上验证 schema 初始化和实际读写。

## 排除项

本架构不包含通用版本化 schema 升级框架、双写同步、读写分离、分库分表、数据库租户隔离、ORM 自动同步 schema、运行时切换数据库或第二数据库后端的兼容层。允许的迁移只有两类：启动时执行的幂等迁移（补列、删遗留表、清理死字段、按目录对账接入点模型），以及按版本记录执行一次的目录数据归一化（`provider_catalog_v1`、`provider_model_catalog_v2`）。后续若出现其他独立迁移需求，应在不破坏 `Storage` 领域边界的前提下另行设计。
