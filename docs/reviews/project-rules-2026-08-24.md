# Prelay 服务端规则审查与处理记录

## 范围

本次只审查工作区总规则、`prelay-server` 规则和 `prelay-protocol` 规则与当前服务端事实的一致性；不评估业务功能，也不评价实际部署环境。

## 已更新

### 密钥变量命名冲突

工作区总规则使用 `PRELAY_MASTER_KEY`，而服务端规则、运行说明和实现均使用 `ENCRYPTION_KEY`。前者会让执行者配置一个服务端不会读取的变量，导致启动时缺少加密主密钥。

已将工作区总规则统一为 `ENCRYPTION_KEY`，并保留“不得写入文档、测试夹具、客户端持久化状态或日志”的边界。

### 双数据库运行数据边界过窄

服务端规则原先只列出 `data/relay.db`，这已不能覆盖 PostgreSQL 部署产生的数据库数据或测试库。规则不需要规定实际部署方式或宿主机路径，现已改为禁止提交 SQLite 数据库文件、PostgreSQL 数据卷或导出、任何运行时数据库数据、`.env` 和所有凭据。

### 同版本重发缺少显式边界

工作区总规则禁止未经授权的标签与发布操作，但没有区分新版本发布和覆盖已发布版本。`v0.1.1` 已按明确授权重发，说明该能力存在且影响较高。

现已补充：已发布标签默认不可移动；只有用户明确要求重发同一版本时，才允许强制更新标签，并且必须重新验证发布工作流和 Release 产物。

## 已有规则

服务端本地规则已加入真实 PostgreSQL 验证要求：数据库初始化、原始 SQL、SeaORM 映射或 PostgreSQL 连接配置变更时，必须使用独立空测试库运行真实 PostgreSQL schema 契约和受影响集成测试。该规则是本次 PostgreSQL 聚合列问题后的必要补充，但当前仅存在于本地提交 `299bcd0`，尚未推送。

协议仓规则的 DTO、错误码、子模块和凭据边界与当前工作区职责一致，无需因本次服务端变化调整。

## 结论

工作区总规则的密钥变量和同版本重发边界，以及服务端规则的数据库数据表述均已更新。没有把 Compose、宿主机目录或实际部署流程写入规则；这些内容属于部署材料，不适用于当前项目规则。
