# provider-relay 工程体系评审报告

## 评审范围

本次评审针对当前 `master` checkout 及全部未提交改动，检查 Rust/Axum 后端、Vue/Vite 管理台、SQLite 数据模型、构建与部署链、测试体系、仓库治理和正式文档的一致性。

评审只判断工程体系、架构边界和交付风险，不评价功能需求是否完整，不把本地静态检查视为真实供应商、真实客户端或生产环境验收。

当前 `master` 与 `origin/master` 同步。工作区有 40 个已跟踪文件变更和 21 个未跟踪文件，已跟踪 diff 为 4805 行新增、2347 行删除。以下结论以当前工作区为准，不代表已提交基线。

## 评审依据

- 用户提供的项目规则，重点包括只读评审边界、根因优先、Node.js 使用 Bun、Rust 验证要求和未验证状态不得表述为完成。
- 工程评审通用基线及 Rust、Vue 专项检查清单。
- 仓库配置：`.editorconfig`、`.gitattributes`、`.gitignore`、`.dockerignore`、`Cargo.toml`、`Cargo.lock`、`build.rs`、`web/package.json`、`web/bun.lock`、Vite、ESLint 和 Prettier 配置。
- 架构和状态文档：`docs/protocol-bridge-gateway-design.md`、`docs/protocol-bridge-implementation-status.md`、`docs/protocol-bridge-next-phase-plan.md`。
- 当前源码、测试、Git 状态和本次实际命令输出。

## 总体结论

项目已经形成可理解的单进程网关结构：协议入口统一经过 interface token 鉴权，`ProviderSpec` 集中维护上游协议能力，桥接层覆盖 Chat Completions、Responses 和 Anthropic Messages，流式统计与 metadata 也有较多自动化测试。当前格式、静态检查、类型检查和构建能够通过。

当前改动尚不具备直接提交或对外发布条件。主要阻断点是管理面默认开放并能枚举可用代理令牌，供应商和接口保存缺少事务边界，接口模型删除没有约束父资源，测试环境存在绕过生产解析链的分支。仓库同时存在依赖获取不可复现、正式文档未覆盖新模型和大规模未提交改动混在一个交付单元的问题。

建议先封闭管理鉴权和数据一致性风险，再收敛测试与生产路径，随后补齐构建、文档和提交治理。真实 Codex、Claude Code、上游供应商及浏览器交互仍需单独验收。

## 主要问题

### 管理面默认开放并可转换为上游调用权限

**级别：高。定性：违反项目已确认规范。**

`src/main.rs:48-51` 在 `ADMIN_TOKEN` 未配置时只告警并继续启动；`src/routes/auth.rs:25-27` 会直接放行全部 `/api` 管理请求。`docker/docker-compose.yml:6-11` 将服务发布到宿主机 3000 端口，并把空字符串作为 `ADMIN_TOKEN` 默认值。

匿名调用 `GET /api/configs` 和 `GET /api/interfaces` 可以取得完整 provider token 或 interface token，见 `src/models.rs:223-255`、`src/models.rs:287-301`。provider token 可继续调用 `/proxy`，后端会取出保存的上游 API Key 代为发起请求，见 `src/routes/proxy.rs:26-32`、`src/routes/proxy.rs:74-81`。风险包括配置和接口被修改或删除、令牌泄露以及上游额度被消耗。

当前前端虽然在 `web/src/api/index.ts:6-12` 读取 `provider-relay-admin-token`，但仓库没有设置该键的界面或文档。开启鉴权后，管理台只能依赖手工写 localStorage，安全能力与可操作性没有形成闭环。

建议默认要求管理凭据；确需匿名开发模式时使用显式环境开关，并限制监听地址。增加缺少凭据时的启动策略测试、匿名管理 API 拒绝测试和管理台鉴权入口。生产部署同时收紧 CORS，避免继续使用 `CorsLayer::permissive()`。

### 供应商和接口保存没有一致性事务

**级别：高。定性：违反硬性工程基线。**

供应商编辑先更新配置，再由前端分别创建和删除模型，见 `web/src/views/ProvidersView.vue:634-703`、`web/src/views/ProvidersView.vue:1019-1044`。接口编辑也先更新接口，再分别删除和创建模型，见 `web/src/views/InterfacesView.vue:340-378`、`web/src/views/InterfacesView.vue:492-514`。

这些操作跨多个 HTTP 请求，任一请求失败都会向用户显示“保存失败”，但此前的配置更新、模型创建或删除已经提交。新建接口时，接口本体创建成功而模型创建失败，还会留下无法从当前表单完整恢复的空接口。接口编辑先删除旧模型再创建新模型，创建失败时会直接丢失原映射。

建议由后端提供“配置加完整模型集合”的单个保存契约，在一个 SQLite 事务内校验并替换子资源。前端只提交目标状态，不承担数据库差集同步职责。回归测试应覆盖创建中断、删除后创建失败和并发修改。

### 接口模型删除没有约束父接口

**级别：中。定性：违反硬性工程基线。**

删除路由声明为 `/interfaces/:_interface_id/models/:model_id`，但 `src/routes/admin.rs:646-654` 丢弃了 `_interface_id`，`src/db.rs:463-468` 仅按全局 `model_id` 删除。请求路径写接口 A，同时传入属于接口 B 的模型 ID，仍会删除 B 的模型。

这破坏了父子资源契约，也使错误的前端状态或运维脚本能够修改错误对象。建议查询和删除条件同时包含 `interface_id` 与 `model_id`，跨接口请求返回 404，并补充对应路由测试。

### 引用完整性只依赖应用层约定

**级别：中。定性：规范缺失导致风险。**

`provider_models`、`interface_configs` 和 `interface_models` 在 `src/db.rs:46-58`、`src/db.rs:113-141` 中没有外键。`create_interface_model` 先独立查询 provider model，再执行插入，见 `src/db.rs:424-451`；并发删除 provider 时可能在两步之间形成悬空引用。当前删除操作通过多条手写 SQL 维护级联关系，新增写路径容易遗漏。

仓库没有 SQL migration 目录，schema 主要由启动时 `CREATE TABLE IF NOT EXISTS` 和单个 `ALTER TABLE` 维护。随着接口、模型和会话实体增加，升级失败、约束补充和回滚都难以审计。

建议引入显式、可回放的数据库迁移，启用 SQLite foreign keys，为稳定父子关系增加 `ON DELETE` 策略，并将校验与写入放入同一事务。迁移前需要检查已有 `data/relay.db` 的脏引用。

### 测试环境绕过了生产模型解析链

**级别：中。定性：违反硬性工程基线。**

生产 `/v1/*` 请求必须先通过 interface token 鉴权，再根据接口模型解析 provider。`src/routes/interface_resolver.rs:15-33` 却在 `cfg(test)` 且请求没有 token 时启用旧的 provider/alias 回退。大量桥接测试直接调用 handler 并传空 HeaderMap，因此验证的是测试专用路径，不是“鉴权、接口、模型映射、协议选择”的生产执行链。

前端 66 个测试中，页面布局类测试主要使用 `readFileSync` 和字符串包含断言，例如 `web/tests/interface-layout.test.ts:1-15`。它们适合保护静态结构，但不能验证组件渲染、请求失败、键盘交互、抽屉焦点、路由历史或响应式布局。

本次首次并行 Rust 全量测试中，`rejects_unauthenticated_anthropic_messages_request` 一次返回 502 而不是 401；单测、串行全套和第二次并行全套均通过。当前无法确认是测试隔离、网络栈瞬态还是其他共享状态，不能把后续通过写成已经解决。

建议移除测试专用业务回退，使用真实 interface、interface model、token 和 middleware 建立三种协议入口的集成 fixture。前端保留纯函数测试，另外补组件挂载测试和少量关键管理流程浏览器 E2E；对本次偶发失败增加重复运行或隔离诊断后再判断根因。

### 模型发现的同步语义与实现不一致

**级别：中。定性：违反项目已确认规范。**

`discover_saved_models` 将发现结果传给 `upsert_provider_models`，但 `src/db.rs:243-267` 只执行 `INSERT OR IGNORE`。上游已经下线的模型不会从本地目录移除，仍可被新接口引用，直到管理员手工删除。

如果该能力定义为“发现并追加”，应统一函数、接口和界面文案；如果定义为“同步”，应在事务内计算权威差集，并明确删除模型时如何处理已有接口映射。需要增加第二次发现结果减少的回归测试。

### 非流式统计失败会覆盖成功的上游结果

**级别：中。定性：建议优化。**

Chat、Messages 和 Responses 非流式路径在上游成功后仍使用 `?` 等待 `insert_request_log`，见 `src/routes/chat.rs:143-190`、`src/routes/messages.rs:181-220`、`src/routes/responses.rs:496-538`。SQLite 写入短暂失败会把已经成功且可能计费的上游请求转换成客户端 500，客户端重试可能造成重复调用。

流式统计已经采用“记录失败只写日志，不截断响应”的策略。建议明确统计是旁路观测还是强一致业务数据；按当前产品文档的观测边界，非流式路径应与流式路径一致地降级，并补 SQLite busy timeout 或受控重试。

### 前端凭据和错误状态治理不完整

**级别：中。定性：违反硬性工程基线。**

`web/src/views/ProvidersView.vue:683-688` 把 provider proxy token 保存到 localStorage。`web/src/utils/providers.ts:379-426` 提供读取、删除和替换函数，但当前源码只有 `saveToken` 调用，令牌没有产品内读取方，会长期作为同源脚本可读的死数据残留。

供应商和接口首次加载没有错误分支，见 `web/src/views/ProvidersView.vue:490`、`web/src/views/InterfacesView.vue:292-303`。请求失败后页面可能显示空态并产生未处理 rejection，用户无法区分“没有数据”和“管理鉴权或网络失败”。

建议移除无用途的 provider token 持久化并提供历史 localStorage 清理逻辑；为管理 API 统一定义 401、网络失败和空数据状态，提供明确重试入口。

### 前端页面和基础交互边界仍然过重

**级别：中。定性：建议优化。**

`ProvidersView.vue`、`StatsView.vue` 和 `InterfacesView.vue` 分别为 1046、807 和 516 行。页面同时承担表单状态、DTO 组装、API 编排、模型差集、错误文案、metadata 解析和大段渲染。当前基础组件只抽出了壳层，领域行为仍集中在页面。

`web/src/components/base/DrawerPanel.vue:2` 没有 dialog role、`aria-modal`、焦点约束、Escape 关闭和关闭后焦点恢复。可点击表格行缺少明确 `focus-visible` 样式，保存结果也没有 live region。字符串测试不能证明这些行为有效。

建议按真实职责提取 provider/interface editor composable、metadata 解析模块和事务型保存命令；在 `DrawerPanel` 一处补齐可访问性契约，再用组件测试覆盖。

### 构建和依赖获取不可复现

**级别：中。定性：违反硬性工程基线。**

`build.rs:18-21` 在 `web/node_modules` 不存在时执行非冻结的 `bun install`。任意 Cargo 检查都可能联网、改变锁文件或解析到不同依赖；本地行为与 `Dockerfile:5` 的 `bun install --frozen-lockfile` 不一致。`build.rs` 的 rerun 输入也没有包含 `web/bun.lock`。

`web/bun.lock` 有 281 个依赖下载地址绑定 `http://pkg.rd.kim`。该内网 HTTP 源没有写入正式构建前提，隔离环境或外部构建无法按锁文件安装。`Dockerfile` 还使用浮动的 `oven/bun:1`、`rust:1-slim` 和未固定版本的 `cargo-chef`。

建议把依赖安装移出 Cargo build script；至少使用冻结安装并在缺依赖时明确失败。锁文件应使用团队可访问的 HTTPS 源或明确记录受限构建环境，发布工具链固定具体版本，正式镜像进一步固定 digest。

### Docker 构建上下文没有排除本地环境文件

**级别：中。定性：规范缺失导致风险。**

`.gitignore:16-17` 忽略 `.env` 和 `.env.local`，`.dockerignore` 却没有对应规则；`Dockerfile:6` 会把整个 `web/` 复制进前端构建层。当前仓库没有已跟踪环境文件，但开发者本地出现 `web/.env*` 时，内容会进入 Docker 构建上下文和缓存层。

建议在 `.dockerignore` 排除根目录及 `web/` 下的 `.env`、`.env.*`，并收窄 Docker `COPY` 范围。敏感构建参数使用 BuildKit secret，不通过普通 ARG、ENV 或文件层传入。

### 正式文档和交付单元未跟上当前实现

**级别：中。定性：违反项目已确认规范。**

当前新增 interface、interface model、provider model discovery 和管理台三页面结构，正式设计文档仍以旧 provider token 和 model alias 为主。`docs/protocol-bridge-gateway-design.md:431-444` 仍写“后续区分管理 API 鉴权”，没有描述当前 `ADMIN_TOKEN` 兼容模式与 interface token 解析关系；实现状态文档也没有覆盖新管理模型。

仓库没有 README，运行参数、管理凭据设置、首次启动、Bun/Rust 版本、数据库升级、备份和验证命令缺少单一入口。当前 40 个已跟踪变更和 21 个未跟踪文件同时混合后端数据模型、协议路由、模型发现、前端组件重构、页面实现、mockup 和结构测试，难以形成可审计提交。

建议先更新正式设计和运行文档，再按“后端接口与模型契约”“前端管理台迁移”“测试与文档”形成清晰提交。拆分应服从依赖顺序，每个提交都保持可构建，不按文件类型机械切分。

### 质量入口和文本策略仍有小缺口

**级别：低。定性：规范缺失导致风险。**

`web/package.json:6-14` 没有独立 `test` 和 `typecheck` 脚本，新增 `web/tests/` 也没有进入 `build.rs` 或现有正式验证说明。测试容易在日常构建中被遗漏。

`.gitattributes` 只有 `* text=auto`，`.editorconfig` 没有 `end_of_line`，Prettier 则固定 LF。本次 `git diff --check` 通过，但 Git 对当前多份修改文件提示后续可能发生 LF/CRLF 转换。

建议补充 `bun test` 和独立 typecheck 入口，并在交付验证中明确调用。换行策略应作为独立格式治理任务确定，不与当前功能改动一起批量归一化。

## 整改优先级建议

### 封闭发布阻断项

- 让管理鉴权默认生效，补齐管理台凭据入口，收紧监听和 CORS 部署边界。
- 提供后端事务型 provider/interface 保存契约，修复接口模型删除的父资源约束。
- 删除测试专用业务回退，建立真实 interface token 的三协议入口集成 fixture。

### 收敛数据与凭据边界

- 引入数据库 migration、外键和稳定级联策略。
- 明确模型发现是追加还是权威同步，并补减少模型的回归测试。
- 移除无读取方的 provider token localStorage 持久化。
- 明确统计写入失败不应覆盖已成功的上游响应。

### 建立可重复交付链

- 移除 Cargo build script 中的隐式依赖安装，统一冻结的 Bun 安装入口。
- 处理内网 HTTP 锁文件来源，固定 Docker 工具链版本，补 Docker 环境文件忽略规则。
- 增加前端 test/typecheck 脚本，补组件行为测试和关键浏览器 E2E。
- 同步正式设计、实现状态和 README，再按可构建逻辑单元整理提交。

### 保留真实验收边界

- 使用真实 Codex、Claude Code 和目标供应商验证非流式、流式、工具调用、usage 和错误路径。
- 对管理台执行桌面与移动视口的浏览器交互、键盘、焦点和截图验收。
- 在生产形态验证数据库升级、并发写入、备份恢复、超时和容器健康策略。
